# your-skill-name

> 这是 `template/` 的模板，本身不是可用的技能。复制整个目录到 `skills/` 下再改名，逐节替换内容。
> 目录名与上面的 `name` 必须完全一致，只用英文小写字母、数字和连字符（如 `log-cleanup`）。

## 用途

**接口摘要**：一句话说清"它接受什么、产出什么"。必须与 frontmatter 的 `description` 第一句一致——两者并排，能力变了却没改摘要时，人一眼能看见矛盾。

（这个技能解决什么问题？一两句话说清，别写背景故事。）

## 文件结构

```
your-skill-name/
├── SKILL.md              必需：元数据 + 指令
├── assets/               可选：模板、示意图、示例数据
├── references/           可选：只放 MLA 格式引用与链接（SOURCES.md），不放原文
└── scripts/              可选：可执行脚本
```

- `SKILL.md` 正文控制在 500 行以内。超了就把细节拆出去：能跑的逻辑进 `scripts/`，背景与出处进 `references/`。
- `references/` 只放 `SOURCES.md`（MLA 引用与链接），**不复制他人文档原文**。原因：仓库公开，复制有版权风险；Git 也删不掉历史里的文件。
- `assets/` 放要用的素材。单个文件超过约 200KB 的二进制（PDF、大图、音视频、数据集）不入库，改在 `references/SOURCES.md` 留引用 + 链接。
- 引用本目录内的文件用相对路径，且只引用一层，例如 `见 [SOURCES.md](references/SOURCES.md)`。

## 依赖

- 运行时：如 Python 3.11 / Node 20 / 纯 shell（无则写「无」）
- 第三方包：如 `requests>=2.31`（无则写「无」）
- 外部服务或凭证：只写环境变量名，如 `需要 MY_API_KEY`，**不要写真实值**

## 使用方法

```bash
# 从仓库根目录执行
./skills/your-skill-name/scripts/run.sh --input <路径>
```

Agent 加载本技能后，按以下顺序执行：

1. 确认输入齐备，缺什么先问用户
2. 执行上面的命令
3. 核对输出，按「注意事项」检查边界情况

## 注意事项

- 会删除、覆盖、联网写入的操作，先向用户确认再执行
- 密钥、token、个人隐私目录的内容不得写入本目录
- 其他边界条件与已知限制
