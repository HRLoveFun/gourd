# 女娲 · Skill 造人术

> 「写不进去的那部分，才是你真正的护城河。」——但写得进去的部分，已经足够强大。

本目录是从 [alchaincyf/nuwa-skill](https://github.com/alchaincyf/nuwa-skill)（MIT）移植的版本：方法、阈值、黑名单与上游一致，只按本仓库约定重排了结构、把细节外置到 `references/`。移植范围与差异见 [references/SOURCES.md](references/SOURCES.md)。

## 用途

**接口摘要**：接受一个人名、一个主题，或一句模糊的思维需求，产出 `[目标目录]`（默认 `[技能目录]/<slug>-perspective/`）人物 Skill 目录；中途在调研、提炼、验证三处停下来等用户确认。

女娲不是复制人，是**提炼思维框架**。一个好的人物 Skill 是一套可运行的认知操作系统：

- 他用什么**心智模型**看世界？（镜片）
- 他用什么**决策启发式**做判断？（直觉规则）
- 他怎么**表达**？（表达 DNA）
- 他**绝对不会**做什么？（反模式）
- 什么是这个 Skill **做不到的**？（诚实边界）

**关键区分**：捕捉的是 HOW they think，不是 WHAT they said。

正文涉及三个目录，各用固定记号，不要混：

- `[本技能目录]`：女娲自己所在目录（本文件处），`scripts/` 与 `references/` 都在这里，直接以 `[本技能目录]/scripts/xxx` 调用
- `[技能目录]`：runtime 的技能安装位置——本仓库是 `skills/`，Claude Code / Codex 是 `.claude/skills/`，其他 runtime 以各自文档为准
- `[目标目录]`：本次要产出的新技能目录，**默认 `[技能目录]/<slug>-perspective/`**；`<slug>` 用英文小写字母、数字、连字符，且与目标 SKILL.md 的 `name` 完全一致。目标是本仓库时，产出后还要在 `CATALOG.md` 登记一行

## 输入

| 项目 | 说明 | 是否必需 |
| --- | --- | --- |
| 人名 / 主题 | 「芒格」「价值投资」「产品克制」 | 与下一行二选一 |
| 模糊需求 | 不知道该蒸馏谁时的一句困惑，如「我总是选错」 | 与上一行二选一 |
| 聚焦方向 | 全面画像，或聚焦某个维度 | 否，默认全面 |
| 本地语料 | 书籍 PDF、访谈/字幕 transcript、博客导出 | 否，有则质量明显更好 |
| 蒸馏档位 | 快速 / 标准 / 深度，见 Phase 0A | 否，默认标准 |

两者都没给：先问一句要蒸馏谁、或者要解决什么困惑，不要凭印象开工。

## 输出

| 产物 | 位置 | 说明 |
| --- | --- | --- |
| 人物 / 主题 SKILL.md | `[目标目录]/SKILL.md` | 最终交付物，含心智模型、表达 DNA、诚实边界 |
| 调研存档 | `[目标目录]/references/research/01-06.md`（快速档只有 01-03） | 每个 Agent 一份，既是断点也是可交付中间产物 |
| 一手素材 | `[目标目录]/references/sources/` | 用户提供与网络下载的原文 |
| 验证结论 | 会话内输出 | Phase 4 三项测试结果与通过标准逐项核对，不落盘 |

更新模式下只做增量改写，不整篇覆盖；用户中途叫停时，已落盘的调研文件可直接续跑。

## 依赖

- 运行时：bash 3.2+、python3 3.8+、支持并行 subagent 的 Agent runtime、联网搜索或抓取工具
- 第三方包：Python 侧只用标准库；`scripts/download_subtitles.sh` 需要 `yt-dlp`
- 外部服务或凭证：无，不需要任何 API key；调研需要联网
- 可选：环境里已装的信息获取 skill（如 `web-article-reader`、`gemini-video`、`pdf`）会被 Phase 1 优先调用

## 使用方法

按 Phase 顺序执行。四个 🔴 CHECKPOINT（Phase 1.5 / 2.5 / 4 / 5）必须停下来等用户确认，不得自行推进。

### Phase 0: 入口分流

| 用户输入 | 路径 | 示例 |
| --- | --- | --- |
| 明确的人名 / 主题 | 直接路径 → Phase 0A | 「蒸馏芒格」「做一个费曼 skill」 |
| 模糊的需求 / 困惑 | 诊断路径 → Phase 0B | 「我想提升决策质量」 |

### Phase 0A: 需求澄清（直接路径）

收到明确名字后，逐条确认：这个人是谁、聚焦哪个维度、用途（思维顾问 / 决策参考 / 角色扮演）、新建还是更新、有没有本地一手素材。第 5 项照原话问：「你手上有没有这个人的一手素材？书籍 PDF、演讲/访谈 transcript、视频字幕、个人博客导出都行，比网上搜的质量高得多。」

然后报出成本量级让用户选档——完整蒸馏是多 agent + 多轮搜索的长任务，顶级模型单次可能消耗数十美元，开跑前必须说清：

| 档位 | 调研规模 | 适用场景 | 成本量级 |
| --- | --- | --- | --- |
| 快速 | 3 个维度（著作+对话+表达），每维度限 5 个来源 | 先试效果 / 冷门人物 / 预算敏感 | 约标准档 1/3 |
| 标准（默认） | 6 个维度完整调研 | 大多数场景 | 中等；换更轻量模型可显著降低 |
| 深度 | 6 维度 + 一手素材全量下载（书籍/字幕/长文存档） | 打算开源发布的精品 | 最高 |

- 档位是「报量级 + 给默认」，不是「等用户点选」：用户说「就做 XX」没给更多信息 → 默认全面画像 + 思维顾问 + 无本地语料 + 标准档，直接推进，不必停下来等档位确认
- **确认不阻塞交付**：能给默认值的都给默认值；下一步产出不依赖用户答案时，先给产出再让用户调整，不要把现成的价值卡在提问之后
- 用户给了本地语料 → 标记**本地语料模式**，Phase 1 采集策略随之调整

### Phase 0B: 需求诊断（模糊路径）

用户只有困惑、不知道该蒸馏谁时，**先读 [references/diagnosis-path.md](references/diagnosis-path.md)**，再按其三步执行：

1. 需求定位：最多追问 2 轮，把困惑映射到决策 / 表达 / 创业 / 教学 / 批判 / 内容 / 人生 / 风险 / 设计 / 幽默之一
2. 候选推荐：给 2-3 个候选，优先展示已有 Skill，每个候选写清「核心镜片 / 为什么适合你 / 局限」
3. 用户选择：选已有 → 直接激活；选新候选 → 回 Phase 0A 确认细节；都不满意 → 回第 1 步

### Phase 0.5: 创建 Skill 目录

**收到确认后立即执行**，在调研之前完成：

```
[目标目录]/
├── SKILL.md
├── scripts/
└── references/
    ├── research/   01-writings.md 02-conversations.md 03-expression-dna.md
    │               04-external-views.md 05-decisions.md 06-timeline.md
    └── sources/    books/ transcripts/ articles/
```

完成检查：目录已建，目录名是 `<slug>-perspective`；中国人物已切到 B 站原始视频 / 小宇宙 / 权威中文媒体（知乎与公众号始终排除）；更新模式已读取现有 SKILL.md 并标出待刷新项；本地语料已复制进 `sources/`。

关键规则：每个 subagent 必须把结果写入对应 md 文件，不落盘的调研等于没做；**所有调研文件必须存在 skill 目录内部**，Skill 要能整目录复制后独立使用。

### Phase 1: 多源信息采集（并行 Agent Swarm）

先定模式：纯网络搜索（默认）/ 本地语料优先 / 纯本地语料。再并行启动 subagent（标准/深度档 6 个；快速档只启 1/2/3，见「特殊场景」），各自写入 `[目标目录]/references/research/0X-*.md`：

| Agent | 搜索目标 | 提取重点 |
| --- | --- | --- |
| 1 著作 | 书、长文、论文、newsletter | 反复出现 ≥3 次的论点（真信念）、自创术语、推荐书单 |
| 2 对话 | 播客、长视频、AMA、深度采访 | 被追问时的回答方式、即兴类比、改变立场的瞬间 |
| 3 表达 | Twitter/X、微博、即刻、短文 | 高频用词句式、争议立场、幽默方式 |
| 4 他者 | 他人分析、书评、批评、传记 | 外部观察到的模式、批评与争议 |
| 5 决策 | 重大决策、转折点、争议行为 | 决策背景、事后反思、言行不一致案例 |
| 6 时间线 | 出生/出道至今 | 关键里程碑、思想转折点、最近 12 个月动态 |

硬性要求：标注来源 URL 与可信度（一手 > 二手 > 推测）；区分「他说过的 / 别人说他的 / 我推断的」；发现矛盾保留矛盾，不和稀泥。

信息源黑名单：**知乎、微信公众号、百度百科**，任何维度都不例外。

> 完整任务分配、prompt 模板、可用脚本、信息源优先级与失败降级表（并行不可用 / 上下文不足 / 成本失控 / 工具不可用）见 [references/research-swarm.md](references/research-swarm.md)。**启动 Phase 1 前必须读它。** 运行时不支持并行 subagent 时按表串行执行，禁止挂起等待后台通知。

### Phase 1.5: 调研 Review 检查点

**🔴 CHECKPOINT** · 各 Agent 落盘后（标准档 6 个，快速档 3 个，见「特殊场景」），暂停展示调研质量摘要：每个 Agent 的来源数、关键发现、矛盾点、信息不足的维度。`python3 [本技能目录]/scripts/merge_research.py [目标目录]` 可直接生成这张表。

用户确认 → Phase 2；某维度不够 → 补充调研后再继续。调研质量决定最终 Skill 的上限，垃圾进垃圾出，在这里拦截比 Phase 4 返工便宜得多。

### Phase 2: 框架提炼（Synthesis）

先读 [references/extraction-framework.md](references/extraction-framework.md) 拿到三重验证方法论，再逐项提炼：

1. **心智模型（3-7 个）**：扫 01-05 列出 15-30 个候选，逐个过三重验证——跨域复现（≥2 个领域出现）、生成力（能推断他对新问题的立场）、排他性（不是所有聪明人都这么想）。三重通过 → 心智模型；1-2 重 → 降级为决策启发式；0 重 → 丢弃。按排他性排序取 top 3-7，宁少勿多。每个记录：名称、一句话、≥2 个场景的证据、应用方式、局限。
2. **决策启发式（5-10 条）**：可写成「如果 X，则 Y」，每条有具体案例。
3. **表达 DNA**：句式偏好、词汇特征、节奏感、幽默方式、确定性表达、引用习惯。
4. **价值观与反模式**：3-5 条核心价值排序、明确反对的行为、价值观之间的内在冲突（深度的来源）。
5. **智识谱系**：受谁影响 → 影响了谁 → 在思想地图上的位置。
6. **诚实边界**：不能预测全新问题、不能替代本人的创造力与直觉、公开表达与真实想法可能有差距、信息截止到调研时点。

### Phase 2.5: 提炼确认检查点

**🔴 CHECKPOINT** · 展示提炼摘要（心智模型 N 个及名称、启发式 N 条、表达 DNA 三个特征、核心张力 N 对、诚实边界 N 条）。

用户确认 → Phase 3；某个模型不对或缺失 → 回 Phase 2 调整。提炼是主观判断最重的环节，在这里确认，好过写完 400 行才发现方向错了。

### Phase 3: Skill 构建

1. 读 [references/skill-template.md](references/skill-template.md) 拿骨架：frontmatter、角色扮演规则、身份卡、心智模型、决策启发式、表达 DNA、时间线、价值观、智识谱系、诚实边界、调研来源。
2. 按骨架逐节填入 Phase 2 的结果：

| 模板 Section | 填充来源 |
| --- | --- |
| frontmatter description | 一句定位 + 明确触发语 + 一句「不在一般性问题上自动触发」；控制在约 300 字内，绝不超过 1024 字 |
| 角色扮演规则 | 直接用模板默认规则（含「未表态主题标推断」「关键引用可分辨」两条输出纪律） |
| 回答工作流 | 由心智模型自动推导，见下 |
| 身份卡 | 时间线 + 著作 → 用此人语气写 50 字自我介绍 |
| 心智模型 / 启发式 / 表达 DNA | Phase 2.1-2.3 结果 |
| 时间线 | Agent 6 结果精简为关键节点表格 |
| 价值观、智识谱系、诚实边界 | Phase 2.4-2.6 结果 + 调研时间 |
| 创建者归属 | `> 本 Skill 由 [女娲](https://github.com/alchaincyf/nuwa-skill) 生成` |

3. **回答工作流（Agentic Protocol）**：必须含 Step 1 问题分类（需要事实 / 纯框架 / 混合）、Step 2 用工具取真实信息、Step 3 以人物口吻输出判断。Step 2 的研究维度**从本次蒸馏出的心智模型反推**，不能写「搜索相关信息」这种通用话。缺这一节，人物遇到事实问题就会凭训练语料编造。
   > 模板全文、按人物推导研究维度的示例、三条关键约束见 [references/answer-protocol.md](references/answer-protocol.md)。
4. 读 [references/extraction-framework.md](references/extraction-framework.md) 末尾的质量自检清单逐项核对，不通过的回对应 Phase 修。
5. 写入 `[目标目录]/SKILL.md`。

### Phase 4: 质量验证

用子 agent 执行，避免自评偏差。`python3 [本技能目录]/scripts/quality_check.py [目标目录]/SKILL.md` 可先把 4.4 的六项跑一遍，输出逐项 PASS/FAIL，省掉手工核对：

- **4.1 已知测试**：选 3 个此人公开表态过的问题，带新 Skill 回答，对比实际立场。方向一致 → 模型有效；偏离 → 回调整模型权重。
- **4.2 边缘测试**：选 1 个相关但没公开讨论过的问题，期望输出是「基于模型 X 和 Y 的推断，可能……但不确定」，斩钉截铁即不合格。
- **4.3 风格测试**：写 100 字分析，判断有表达特征、不是通用 AI 鸡汤、不是原话拼凑。
- **4.4 通过标准**：

| 检查项 | 通过标准 | 不通过信号 |
| --- | --- | --- |
| 心智模型数量 | 3-7 个，每个有来源证据 | <3；>7 时须在验证报告里说明为什么超出 |
| 每个模型的局限性 | 明确写出失效条件 | 只写优点 |
| 表达 DNA 辨识度 | 读 100 字能认出是谁 | 像通用 ChatGPT |
| 诚实边界 | ≥3 条具体局限 | 只有「不能替代本人」 |
| 内在张力 | ≥2 对矛盾 | 观点高度一致（太假） |
| 一手来源占比 | >50% | 主要依赖二手转述 |

不通过 → 标注薄弱项回 Phase 2，**Phase 2→4 最多循环 2 次**；2 轮后仍不通过就把薄弱维度写进诚实边界，交付当前最优版本，不无限打磨。

**🔴 CHECKPOINT** · 展示验证结果，用户确认后才算完成。

### Phase 5: 双 Agent 精炼（标准后置工序）

Phase 4 通过后自动并行两个 Agent：A 按 8 个结构维度打分（工作流清晰度、失败模式编码、检查点设计、可执行具体性、资源整合、整体架构、反例黑名单、实测表现，各 1-10 分；锚点用 3=该维度缺失、5=有但不可执行、8=具体可执行、10=有示例且有反例；装了 `skills/darwin-skill/` 时直接照它的 9 维表取 dim2-dim9，两处口径一致）+ 干跑 3 个测试 prompt，给出最弱 2 维的具体改法（附改后文本）；B 从 skill-creator 视角审「激活触发条件是否覆盖真实场景」「角色扮演规则是否可操作（问题路由、频率约束、失败预防）」，给 2-3 处改动。

**🔴 CHECKPOINT** · 综合两份报告，应用不冲突的改进，展示变更摘要请用户确认。精炼标准是「激活即执行」：AI 拿到后知道先做什么、碰到什么停下来，而不只是内容变多。

### 更新已有 Skill

用户说「更新 XX 的 skill」时：读现有 SKILL.md，从诚实边界找出调研时间并标注距今多久 → 只启动 Agent 2（最新对话）、5（最新决策）、6（时间线）→ 新信息强化模型则补案例，与模型矛盾则标注变化并更新，出现新思维模式才考虑加模型 → 更新「最新动态」与调研时间。**增量更新，不重写整个 Skill。**

### 特殊场景

| 场景 | 处理 |
| --- | --- |
| 活人 vs 历史人物 | 活人标注截止日期并建议定期更新；历史人物多源交叉验证，防传记偏差 |
| 主题 Skill（非人名） | 目录改 `<topic>-framework/`；先搜 3-5 个核心流派再按人物分配 Agent；提取领域共识 + 各家分歧；去掉角色扮演与身份卡，改「框架概览」+「流派对比」 |
| 中国人物 | B 站原始视频、小宇宙原始音频、36 氪/晚点/财新/极客公园等权威媒体、本人著作与微博 |
| 冷门人物（可用来源 <10 条） | Phase 0.5 就告知质量受限；心智模型减到 2-3 个并标「基于有限信息推测」；诚实边界加大篇幅 |
| 蒸馏用户自己 | 只能靠用户提供素材；提示自我认知偏差，可追问身边人评价 |
| 快速档（只跑 3 维） | 只启 Agent 1/2/3（著作/对话/表达），Phase 1.5 只展示这三维；Phase 2 的模型数可减到 3-5 个；4.4 的「一手来源占比」与「内在张力」判据降级，并在诚实边界写明「未做他者/决策/时间线维度」。`merge_research.py` 报缺维度属预期，不是信息不足 |

## 注意事项

### 品味守则（速查）

| 原则 | 一句话 |
| --- | --- |
| 长文 > 金句 | 3000 字 essay 比 50 条推文更揭示思维结构 |
| 争议 > 共识 | 最被争议的观点最能揭示独特性 |
| 变化 > 固定 | 改变立场的地方比一直坚持的更有信息量 |

### ❌ 反模式黑名单（绝不做的事）

| # | 反模式 | 为什么 / 替代做法 |
| --- | --- | --- |
| 1 | 编造此人没说过的话 | 引语必须有出处，查不到原文的金句宁可不用 |
| 2 | 把通用道理包装成「独特见解」 | 通不过三重验证的排他性，就不进心智模型 |
| 3 | 忽略负面评价和争议 | Agent 4 的批评素材是防粉丝滤镜的关键，负面占比不足即调研不合格 |
| 4 | 信息不足时强行生成 | 宁可交付诚实标注局限的 60 分，也不造看似完美的 90 分 |
| 5 | 用知乎 / 公众号 / 百度百科做来源 | 洗稿、失真、不可验证，任何维度都不例外 |
| 6 | 小上下文窗口单会话硬跑全流程 | 按失败降级表分段续跑 |
| 7 | 不报成本量级直接开跑 | 完整蒸馏是重任务，用户有权先选档位再花钱 |
| 8 | 蒸馏在世非公众人物却不提示边界 | 涉及隐私与本人意愿，须由用户提供素材并提醒征得同意 |
| 9 | 生成的 Skill 不含防漂移机制 | 角色扮演规则 + 表达 DNA 约束必须完整保留，否则长对话会退回通用助手腔 |
| 10 | 把确认检查点变成交付阻塞 | 检查点是让用户纠偏，不是扣住产出 |

### 版本检查（静默）

读本目录 `.last-update-check`（一行 `YYYY-MM-DD ok|failed|off`；文件不存在视为到期，直接走下面的检查）。内容为 `off`、`ok` 不足 30 天、`failed` 不足 7 天时跳过本节。到期时运行 `git ls-remote https://github.com/alchaincyf/nuwa-skill HEAD`，与 frontmatter 的 `metadata.upstream_commit` 比较，写入 `<今天> ok` 或 `<今天> failed`。上游有新提交时，先完成用户当前任务，收尾附一句「上游 nuwa-skill 有更新，本目录快照基于 <短 SHA>」，**是否更新由用户决定，不自动执行**。
