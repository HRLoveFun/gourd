# doc-architecture

## 用途

**接口摘要**：接受项目根路径与模式（创建 / 重构 / 体检），产出 `AGENTS.md` 文档地图、分层文档骨架、可落地的对账脚本与门禁片段；只建结构与头信息，不代写正文，不自动 git 提交。

文档漂移不是"写得不够勤"，是**同一事实有第二个可写的家**。进度在 README 写一遍、在 STATUS 写一遍、在 commit message 再写一遍，三处各自演化，一个季度后谁都不知道哪句是真的。Agent 在这种仓库里只能猜：猜该读哪份、猜哪句过期、猜做到哪了。

本技能只做四件事：分层、路由、只留一个家、把能对账的部分交给脚本。其余一律不做。

## 文件结构

```
doc-architecture/
├── SKILL.md                  本文件
├── assets/
│   ├── agents-template.md    L0 骨架：docmap 标记 + 五列地图 + 豁免块 + 元规则位 + 改动协议
│   ├── doc-templates.md      STATUS / ARCHITECTURE / CONVENTIONS / ADR / L2 五份骨架
│   └── gate-config.md        pre-commit hook 与 GitHub Actions 两段配置
├── references/SOURCES.md     MLA 引用 + healthcheck + 使用事件
└── scripts/doc-check.sh      六项对账，bash 3.2，无第三方依赖
```

- `assets/` 是**拷出去用**的骨架，不是让 agent 读着照抄的范文。拷贝后按项目改写，占位句一律删。
- `scripts/doc-check.sh` 是**种子**：落地时复制成项目的 `scripts/doc-check.sh`，此后由项目维护。原因见「注意事项 · 已知限制」。
- 没有 `init` 脚本：创建文档体系的核心是判断（选档、并文档、处置旧文档），脚本只能产空壳，空壳立刻成为新的漂移源。

## 输入

| 项目 | 说明 | 是否必需 |
| --- | --- | --- |
| 项目根路径 | 绝对路径，可读可写 | 是 |
| 模式 | `创建` / `重构` / `体检`；不给则按第 0 步自行判定并说明依据 | 否 |
| 档位 | `最小` / `标准` / `长期`；不给则按规模提议，等确认 | 否 |
| 必留文件名 | 客户要求或团队习惯（例如必须保留 `README.md`） | 否 |
| 门禁 | `pre-commit` / `CI` / 两者 / 都不接 | 否，默认两者 |
| 覆盖范围 | 重构时圈定的目录；monorepo 必填 | 重构时必需 |

缺根路径、或用户只说「帮我整理下文档」而没给对象：先问路径，不要按印象挑一个项目开工。

目标只读（别人的仓库、归档快照）：可以体检并出报告，**不落盘**，按「输出」里的报告形态交付。

## 输出

| 落盘物 | 位置 | 覆盖规则 |
| --- | --- | --- |
| `AGENTS.md` | 项目根 | 不存在则新建；已存在只**插入或替换 docmap 块**，其余段落不动；要改其余段落先列清单并确认 |
| L1 文档 | 「进门三件」（`AGENTS.md` `STATUS.md` `README.md`）在根；其余 L1 在 `docs/` | 已存在则保留正文，只补首部元信息行 |
| L2 / L3 | `docs/` | 新建；需移动的走「迁移映射表」 |
| `scripts/doc-check.sh` | 项目 `scripts/` | **不覆盖**同名脚本；已存在则报差异，交用户决定 |
| 门禁配置 | `.git/hooks/`、`.github/workflows/` | 只打印片段，不代写、不改 git 配置 |

**重构模式必附两张表**（在对话里给，不落盘）：

1. **迁移映射表**：`旧路径 | 新归属 | 动作（保留 / 并入X / 降为L3 / 归档 / 删除）| 依据`。每份旧文档必须有归宿，不允许「暂不处理」。
2. **冲突清单**：同一事实的两处说法冲突时列进来，写清判据（代码或可运行证据优先）与待裁决项。

**验收**：在项目根跑 `bash scripts/doc-check.sh` 退出码 0；对话里给运行输出摘要。

不产出：文档正文（只建骨架与头信息）、对项目代码的修改、git commit。

## 依赖

- 运行时：bash 3.2+（macOS 自带版本即可）、`git`（只读：`ls-files`、`log`）
- 命令：`awk` `sed` `grep` `find` `sort` `wc` `mktemp`
- 第三方包：无
- 外部服务或凭证：无，全程不联网
- Windows：只在 WSL / Git Bash 下验证过路径语义，**未验证**；原生 PowerShell 不适用

## 使用方法

六步，顺序固定。第 1 步只记录不判断，第 2 步起才判断。停顿分两类：**进度确认点**两个（第 2 步末的「治哪几条」、第 4–5 步落盘前的结构清单）；**不可逆动作**每次都要单独确认——删文档、改 `AGENTS.md` 地图以外的段落、覆盖既有脚本、写钩子或 CI。

### 0. 判模式

| 现场 | 模式 | 走哪几步 |
| --- | --- | --- |
| 无 `AGENTS.md`，也没有讲设计 / 进度 / 计划的既有文档 | 创建 | 1 → 6 |
| 无 `AGENTS.md`，但有上述既有文档 | 重构 | 1 → 6，第 5 步含迁移 |
| 有 `AGENTS.md`，无 docmap 块 | 重构 | 1 → 6，先补地图再归位 |
| 有 docmap 块 | 体检 | 直接第 6 步，按报告处置 |
| 有地图，但缺「何时改」列或状态乱 | 重构（局部） | 2 → 6，只动有病的那几行 |

判据落在**有没有旧文档要处置**，不落在文件数量——模式决定的是「要不要出迁移映射表」。判不准时按重构走：多出一张映射表，成本低于漏处置一批旧文档。

用户说「重构」不等于全拆。**范围由病象定，不由形容词定**：第 1 步盘出病象，把「这次治哪几条」交用户确认。

### 1. 盘点：只记录，不判断

```bash
cd <root>
git ls-files '*.md' | head -n 200                 # 有哪些文档
git ls-files '*.md' | wc -l                       # 规模
git log -1 --format=%cs -- <路径>                  # 每份最后一次改动
grep -rn --include='*.md' -E '已完成|进行中|进度|TODO' . | head -n 40
```

非 git 仓库：前两条换成 `find . -name '*.md' -not -path './node_modules/*'`，`git log` 换成 `ls -l` 看 mtime；`doc-check.sh` 本身不依赖 git，照跑。

对每份文档记 6 格（表在对话里给，不落盘）：

`路径 | 现在实际回答什么 | 谁在读（地图 / 被引用 / 没人） | 最后改动 | 与代码是否一致 | 病象`

一致性只抽查能验的：文档里写的命令能不能跑、路径是否存在、模块表里的目录是否存在、STATUS 声称完成的批次有没有对应代码或测试。**不能验的项写「未验证」，不要凭印象判一致。**

### 2. 判病象（7 类）并定范围

| # | 病象 | 判定 | 处置方向 |
| --- | --- | --- | --- |
| 1 | 入口缺失 | 无 `AGENTS.md`，或 L0 不指向任何 L1 | 新建地图 |
| 2 | 多副本 | 同一事实（版本号、端口、批次名、命令）在 ≥2 处都能改 | 定一个家，其余改指针 |
| 3 | 死文档 | 无人引用 + 与代码不符 + 引用它的地方已消失 | 归档或删除 |
| 4 | 过肥 | L0 > 120 行，或 L1 > 200 行 | 下沉到 L2 或删 |
| 5 | 层次错位 | L0 里写实现细节；L3 的历史被当现状读 | 搬家 |
| 6 | 假进度 | STATUS 说完成，无证据或与代码矛盾 | 回填证据或降级状态 |
| 7 | 无归属 | 全文没写「我负责回答什么」，也没有「何时改」 | 补元信息或并掉 |

**一条病象都判不出来 → 不要重构。** 按体检模式出报告，然后停。

**确认点一：不阻塞。** 一行交代后继续做，用户回「停」或改范围再调；不必等回复。确认点二（结构清单）是阻塞的，见第 4 步。

> 这次治 2、6、7 三条；3 号那批历史文档我不动，只在地图上标为归档。

### 3. 定档与文档集

| 档 | 适用 | 文档集 | 升档触发 |
| --- | --- | --- | --- |
| 最小 | 单人、小工具、几周收尾 | `AGENTS.md` + `STATUS.md`（已有 `README.md` 就保留并进地图） | 出现第二个模块 |
| 标准 | 持续迭代、有模块划分 | 最小 + `README.md`；`docs/ARCHITECTURE.md` `docs/CONVENTIONS.md` | 出现「当初为什么否掉 A 方案」的追问 |
| 长期 | 多批次、多 agent、要追溯 | 标准 + `docs/adr/` `docs/plans/` `docs/evidence/` `docs/archive/` | — |

**落盘位置固定**：进门三件（`AGENTS.md` `STATUS.md` `README.md`）在根，其余进 `docs/`。理由：根目录每多一份，第一眼要扫的清单就长一分；`README.md` 必须在根，它是仓库名片。既有项目已有自己的布局时，**沿用既有布局**，只改地图，不搬文件。

**层数由判据算，不由档位抄**：每一层必须被上一层某一行指到，指不到的那层不要建。一份文档只属于一层。

| 层 | 回答什么 | 预算 | 谁读 |
| --- | --- | --- | --- |
| L0 | 我该看哪份？文档怎么改？ | ≤120 行 | 每次会话的 agent |
| L1 | 项目是什么、现在到哪、结构如何、什么规矩 | 每份 ≤200 行 | 接手任务的人与 agent |
| L2 | 这个模块/机制为什么这样、怎么改它 | 无硬限，须被 L1 指到 | 要动该模块的人 |
| L3 | 当时怎么想、试过什么、证据在哪 | 不限，append-only | 追溯者与复核者 |

### 4. 落 L0：`AGENTS.md`

**确认点二：阻塞。** 写盘前一次给出结构清单，等确认再写：要建哪些文件（含完整路径）、每份回答什么问题、哪些旧文档要移动或删除、`AGENTS.md` 是否要改地图以外的段落。清单未获确认不得写盘——此时改动成本接近零，写下去之后每一步都要用户回头核对。

拷贝 `assets/agents-template.md`，五块顺序固定：

1. 定位（≤2 行）
2. 当前状态指针（一行：去看 `STATUS.md` 的哪一节；**不在这里复制进度**）
3. 文档地图（`<!-- docmap:begin -->` … `<!-- docmap:end -->` 包裹，五列：`路径 | 层 | 回答什么 | 何时读 | 何时改`）
4. 元规则（≤5 条，只准两类：路由规则、文档维护规则）
5. 改动协议（三步顺序 + 验收命令）

四条硬约束：

- **地图写读者的问句，文档头写文档的边界。** 两处都写范围，必有一份先腐坏；判据：地图那一列能用「？」结尾，文档头那句不能。
- **地图行必须对应真实文件。** 拷模板后先删掉本项目不建的行；不许为了占位建空文档（空文档会被下一次会话当权威读）。`AGENTS.md` 自己也要有一行——地图是完整清单，不是"其余文档清单"。
- **产品与技术规范一律下沉。** `AGENTS.md` 里出现接口定义、表结构、命名条款，说明第 4 块被撑破：搬到 `docs/CONVENTIONS.md`，这里只留一行指针。
- **L0 超预算就下沉，不许缩句糊过去。** 缩句只是把同样的上下文换个说法继续占坑。

### 5. 落 L1 / L2 / L3

每份被地图指向的文档，首部（H1 之后空一行）必须有：

```markdown
> L1 | 权威：项目现状、批次进度、已知未完成 | 不权威：结构、约定、决策理由
```

- `权威` 写它**负责**回答什么；`不权威` 写**最容易被人误用到这里**的那类事实。第二句比第一句有用——它直接掐死「顺手把别处内容也写进来」。
- 读写时机只在地图，不重复写在这里（两处都写就是第二个可写副本）。

`STATUS.md` 另有规格，它是 agent 判断「下一步做什么」的唯一依据：

```markdown
# 状态

当前焦点：<一句话，指到具体批次或问题>

| 批次 | 目标 | 状态 | 证据 | 更新日期 |
| --- | --- | --- | --- | --- |
| F1 | 建数据层 | 已完成 | `tests/test_store.py` 12 passed；commit a1b2c3d | 2026-10-20 |
| F2 | 接口层 | 进行中 | `docs/plans/F2.md` | 2026-10-26 |
```

- 状态只允许五个值：`未开始` / `进行中` / `已完成` / `受阻` / `已取消`。
- **`已完成` 必须填证据**：路径、可复跑命令、commit/PR 三者之一。填不出 → 只能写 `进行中（待验证）`。
- 过程叙述进 `plans/`，不进这张表。表只记结果与证据。
- 取消的批次保留行，状态改 `已取消` 并写原因；删行等于抹掉历史。

L2 与 L3 的骨架见 `assets/doc-templates.md`。填不出内容的文档**不要建**——空文档会被下一次会话当权威读。

### 6. 对账与挂门禁

```bash
cp <技能>/scripts/doc-check.sh <root>/scripts/doc-check.sh
bash <root>/scripts/doc-check.sh --root <root>
```

| 退出码 | 含义 | 处置 |
| --- | --- | --- |
| 0 | 通过（可能有 WARN） | 收工；WARN 逐条记下理由 |
| 1 | 有 FAIL | 按输出逐条修，改完重跑；不许跳过 |
| 64 | 找不到 `AGENTS.md`，或参数错 | 回第 4 步 |

六项检查：

| # | 检查 | 不通过 |
| --- | --- | --- |
| 1 | `AGENTS.md` 存在且含 docmap 块 | FAIL |
| 2 | 地图每行路径存在 | FAIL |
| 3 | 仓库内 `.md` 都被地图覆盖，或写在豁免块里 | FAIL |
| 4 | 被索引文档首部有 `> Lx \| 权威：… \| 不权威：…` | WARN |
| 5 | `STATUS` 状态值合法；`已完成` 行证据非空 | FAIL |
| 6 | 文档内相对链接目标存在 | WARN |

失败路径：

- 退出码 64 但根目录确实有 `AGENTS.md` → 地图标记拼错，按 `assets/agents-template.md` 对齐。
- 第 3 项一片红 → 先加豁免（生成物、临时报告），再逐份归位；**不要为了过检把文件全堆进地图**。
- 第 5 项报状态值非法 → 有人写了「基本完成」这类词；改成五个枚举值之一，过程写进 `plans/`。
- 脚本报 `syntax error` → 项目里的副本被改坏了；重新拷贝，改动提回本技能。

**挂门禁**：片段见 `assets/gate-config.md`。只打印、不代写——改 `.git/hooks` 会影响同仓库所有人，CI 文件要提交，属于用户的仓库决策。

### 7. 维护：写入时机表

维护不是「记得更新文档」，是每类改动都有指定动作。把这张表原样放进 `AGENTS.md` 第 5 块（或放 `CONVENTIONS.md` 并在地图指过去）。

| 事件 | 必改（按顺序） | 不用改 |
| --- | --- | --- |
| 一批任务收尾 | `STATUS` 该行状态 + 证据 + 日期 | `ARCHITECTURE`（结构没变时） |
| 新增/删除模块、依赖方向变 | `ARCHITECTURE` 模块表 → 地图 → 新 L2 | `README`（启动方式没变时） |
| 做了取舍、否掉了方案 | 新 ADR → `ARCHITECTURE` 对应行加指针 | `STATUS` 只记结果 |
| 对外用法变了 | `README` 用法段 | `CONVENTIONS` |
| 改了约定 | `CONVENTIONS` → 若约束 agent 行为，加进 `AGENTS.md` 元规则 | L2 细节 |
| 文档结构变化 | **先**地图 → 再动文件 → 跑 `doc-check.sh` | 其余 |
| 文档与代码冲突 | 描述性文档：改文档；规范性文档：改代码或记例外 | 不许两边各改一半 |
| 文档被取代 | 首部加 `已被 <新文档> 取代`，或移 `archive/` | 不许静默删除 |

**算做完的标志是 `doc-check.sh` 退出码 0**，不是「我改完了」。

**定期体检**（每月，或每 20 次提交）：对地图里每份文档跑 `git log -1 --format=%cs -- <路径>`；超过 180 天未改、且 `grep -rl <文件名>` 找不到任何引用 → 列进候选归档，交用户确认后移 `archive/`。

## 注意事项

### 冲突裁决：先分描述性还是规范性

文档与代码不一致时，先分类再决定改哪边。判错方向会把正确的代码改成错的。

| 类型 | 例子 | 冲突时 | 依据 |
| --- | --- | --- | --- |
| 描述性 | 现状、结构、进度、模块清单 | 文档错，改文档 | 代码是事实 |
| 规范性 | 约定、契约、需求、安全要求 | 代码错，改代码；做不到就记例外 | 文档是承诺 |
| 分不清 | 一处写「应该」、一处写「实际」 | 进冲突清单，交用户裁决 | 不要自己选一边 |

### 异常与边界

| 场景 | 处理 |
| --- | --- |
| 项目不是 git 仓库 | 仍可建；「最后改动」改看文件 mtime；`doc-check.sh` 不依赖 git，照跑 |
| 已有 `AGENTS.md` 但无地图 | 按重构：先加 docmap 块，再把既有段落归位；**不整篇重写**，要删的段落列清单确认 |
| `CLAUDE.md` / `.cursorrules` 已存在 | `AGENTS.md` 为唯一权威，其余做软链 `ln -s AGENTS.md CLAUDE.md`。两个真文件即第二个可写副本 |
| 200 份以上 `.md`、monorepo | 只覆盖用户圈定范围；地图按目录分节，未覆盖的目录在地图末尾列一行「未纳入」 |
| 文档全是 API 参考 | 不迁进 L2；生成式文档交给生成工具，地图只留一个指针 |
| 用户要求「顺手把内容也改好」 | 结构重构与内容修订分两次做、各自验收；混在一次里，失败时分不清哪一步错 |
| 旧文档几千行历史 | 不搬正文；路径进地图（L3），文件移 `archive/`，git 历史保留 |
| 两份文档都像权威且互相矛盾 | 进冲突清单；先按「代码/可运行证据优先」给建议，由用户定 |
| 地图某行指向目录 | 允许（`adr/` 一行代表整目录）；目录内新增文件不再逐一登记，须在该行「何时改」里写清 |
| 用户中途离场 | 停在已确认范围，不自行扩大；已落盘部分跑一次 `doc-check.sh` 留下状态 |

### 铁律

- **地图先行**：改结构先改地图，再动文件，最后对账。顺序反了，所有读地图的 agent 都读到假图。
- **不静默删除**。删任何文档前列清单、给替代归属、等确认。归档优先于删除。
- **不代写正文**。骨架与头信息是产物；正文属于项目，代写的正文必然与代码脱钩。
- **L0 超预算就下沉**，不许缩句、不许换个说法继续占坑。
- **不许写 `基本完成` `大概做完`**。状态只有五个枚举值；写不准就写进 `plans/`。
- **`doc-check.sh` 只查能对账的部分**。它不评价「写得好不好」——那会退化成打分器，还会让人以为漂移已被自动治理。

### 反模式

| 错法 | 为什么错 / 替代 |
| --- | --- |
| 复制一份 README 当 STATUS | 第二个可写副本，必然分叉。进度只在一个地方写 |
| 用目录结构代替地图 | 目录说明不了「何时读、何时改」，agent 仍要逐份打开 |
| 把规范条文抄进 `AGENTS.md` | 每次会话都付这份上下文；改成一行指针 + 锚点 |
| 为凑层数建空文档 | 指不到就不建；空文档会被当权威读 |
| 让脚本判「内容质量」 | 只能对账结构与枚举值；质量判断交给人和复审 |
| 用图片 / mermaid 画结构 | agent 读不了；用表格 + 路径，能 grep |
| 把计划文档当进度看 | L3 是历史，不是现状；现状只在 `STATUS` |
| 一次重构顺手改内容 | 失败时分不清是结构错还是内容错；分两批 |

### 已知限制

- `doc-check.sh` 复制进项目后**不随技能更新**。这是刻意的：hook 与 CI 必须能在没有本技能副本的机器上跑。要同步时人工比对 `diff <技能>/scripts/doc-check.sh scripts/doc-check.sh`。
- 地图覆盖检查按 `.md` 全量比对，对生成物多的仓库会吵。豁免写在 docmap 豁免块内，不要靠临时改脚本绕过。
- 本技能不判断「该不该有这个功能」，也不审文档内容是否正确——那是 `ai-engineering-audit` 与 code review 的范围。
