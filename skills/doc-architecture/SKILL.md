# doc-architecture

## 用途

**接口摘要**：接受项目根路径与模式（创建 / 重构 / 体检），产出入口 `AGENTS.md`、文档超出进门三件时的地图 `DOC_MAP.md`、分层文档骨架、可落地的对账脚本与门禁片段；只建结构、头信息与标签，不代写正文，不自动 git 提交。

文档漂移不是"写得不够勤"，是**同一事实有第二个可写的家**。进度在 README 写一遍、在 STATUS 写一遍、在 commit message 再写一遍，三处各自演化，一个季度后谁都不知道哪句是真的。Agent 在这种仓库里只能猜：猜该读哪份、猜哪句过期、猜做到哪了。

本技能只做四件事：分层、路由、只留一个家、把能对账的部分交给脚本。其余一律不做。

## 文件结构

```
doc-architecture/
├── SKILL.md                  本文件
├── assets/
│   ├── agents-template.md    L0 入口骨架：定位 + 状态指针 + 地图指针 + 元规则 + 改动协议
│   ├── doc-map-template.md   L0 地图骨架：用法 + 三类词表 + 文档行 + 豁免块
│   ├── doc-templates.md      STATUS / README / ARCHITECTURE / CONVENTIONS / ADR / L2 六份骨架
│   └── gate-config.md        pre-commit hook 与 GitHub Actions 两段配置
├── references/SOURCES.md     MLA 引用 + healthcheck + 使用事件
└── scripts/
    ├── doc-check.sh          九项对账，bash 3.2，无第三方依赖
    └── doc-check.test.sh     回归测试，只在本仓跑，不拷进项目
```

- `assets/` 是**拷出去用**的骨架，不是让 agent 读着照抄的范文。拷贝后按项目改写，占位句一律删。
- `scripts/doc-check.sh` 是**种子**：落地时复制成项目的 `scripts/doc-check.sh`，此后由项目维护。原因见「注意事项 · 已知限制」。
- 没有 `init` 脚本：创建文档体系的核心是判断（选档、并文档、处置旧文档），脚本只能产空壳，空壳立刻成为新的漂移源。

## 输入

| 项目 | 说明 | 是否必需 |
| --- | --- | --- |
| 项目根路径 | 绝对路径，可读可写 | 是 |
| 模式 | `创建` / `重构` / `体检`；不给则按第 0 步自行判定并说明依据 | 否 |
| 档位 | `最小` / `标准` / `长期`；不给则按第 3 步的「适用」列提议，并入确认点二 | 否 |
| 必留文件名 | 客户要求或团队习惯（例如必须保留 `README.md`） | 否 |
| 门禁 | `pre-commit` / `CI` / 两者 / 都不接 | 否，默认两者 |
| 覆盖范围 | 重构时圈定的目录 | 否，默认全仓（隐藏目录除外）；monorepo 必须问 |

缺根路径、或用户只说「帮我整理下文档」而没给对象：先问路径，不要按印象挑一个项目开工。

目标只读（别人的仓库、归档快照）：可以体检并出报告，**不落盘**，按「输出」里的报告形态交付。

## 输出

| 落盘物 | 位置 | 覆盖规则 |
| --- | --- | --- |
| `AGENTS.md` | 项目根 | 不存在则新建；已存在只**插入或替换地图指针段**，其余段落不动；要改其余段落先列清单并确认 |
| `DOC_MAP.md` | 项目根，文档超出进门三件时才建 | 不存在则新建；已存在只改词表、文档行与豁免块 |
| L1 文档 | `STATUS.md`、`README.md` 在根；其余 L1 在 `docs/` | 已存在则保留正文，只补首部元信息行；确认点二列出的病象处置除外（如把副本改成指针） |
| L2 / L3 | `docs/` | 新建；既有文档原地保留，只补首部元信息行；需移动的走「迁移映射表」 |
| `scripts/doc-check.sh` | 项目 `scripts/` | **不覆盖**同名脚本；已存在则报差异，交用户决定 |
| 门禁配置 | `.git/hooks/`、`.github/workflows/` | 只打印片段，不代写、不改 git 配置 |

**重构模式必附两张表**（随确认点二在对话里给，不落盘）：

1. **迁移映射表**：`旧路径 | 新归属 | 动作（保留 / 并入X / 降为L3 / 进豁免块 / 归档 / 删除）| 依据`。每份旧文档必须有归宿，不允许「暂不处理」。
2. **冲突清单**：同一事实的两处说法冲突时列进来，写清判据（代码或可运行证据优先）与待裁决项。冲突要逐条得到答复，用户只回“确认”不算裁决；没有裁决的条目写进 `STATUS.md` 的「已知风险」，否则下一次会话只看得到文档头，看不到冲突。

**验收**：在项目根跑 `bash scripts/doc-check.sh` 退出码 0；对话里给运行输出摘要。

不产出：文档正文（只建骨架、头信息与标签）、对项目代码的修改、git commit。

## 依赖

- 运行时：bash 3.2+（macOS 自带版本即可）、`git`（只读：`ls-files`、`log`）
- 命令：`awk` `sed` `grep` `find` `sort` `wc` `mktemp`
- 第三方包：无
- 外部服务或凭证：无，全程不联网
- Windows：只在 WSL / Git Bash 下验证过路径语义，**未验证**；原生 PowerShell 不适用

## 使用方法

步骤顺序固定。第 1 步只记录不判断，第 2 步起才判断。需要和用户对齐的地方分两类：**进度确认点**两个（第 2 步末的「治哪几条」不阻塞，第 4 步写盘前的结构清单阻塞）；**不可逆动作**每次都要单独确认——删文档、改 `AGENTS.md` 地图指针以外的段落、覆盖既有脚本。钩子和 CI 只打印片段，不写入。

### 0. 判模式

| 现场 | 模式 | 走哪几步 |
| --- | --- | --- |
| 无 `AGENTS.md`，也没有讲设计 / 进度 / 计划的既有文档 | 创建 | 1 → 6 |
| 无 `AGENTS.md`，但有上述既有文档 | 重构 | 1 → 6，第 5 步含迁移 |
| 有 `AGENTS.md`，无 `DOC_MAP.md`，文档超出进门三件 | 重构 | 1 → 6，先建地图再归位；手写文档清单和旧 docmap 块在这一步迁走 |
| 有 `AGENTS.md`，无 `DOC_MAP.md`，文档没超出进门三件 | 体检 | 直接第 6 步，按最小档处置 |
| 有 `DOC_MAP.md` | 体检 | 直接第 6 步，按报告处置 |
| 有 `DOC_MAP.md`，但标签缺段、词表失修或状态乱 | 重构（局部） | 2 → 6，只动有病的那几行 |

判据落在**有没有旧文档要处置**，不落在文件数量——模式决定的是「要不要出迁移映射表」。判不准时按重构走：多出一张映射表，成本低于漏处置一批旧文档。

用户说「重构」不等于全拆。**范围由病象定，不由形容词定**：第 1 步盘出病象，第 2 步末把「这次治哪几条」告诉用户。

### 1. 盘点：只记录，不判断

```bash
cd <root>
git -c core.quotepath=off ls-files '*.md' | grep -vE '(^|/)\.' | head -n 200   # 有哪些文档（隐藏目录不算）
git -c core.quotepath=off ls-files '*.md' | grep -vE '(^|/)\.' | wc -l         # 规模
git log -1 --format=%cs -- <路径>                  # 每份最后一次改动
grep -rn --include='*.md' -E '已完成|进行中|开发中|基本完成|进度|TODO' . | head -n 40
```

非 git 仓库：前两条换成 `find . -name '*.md' -not -path './node_modules/*'`，`git log` 换成 `ls -l` 看 mtime；`doc-check.sh` 本身不依赖 git，照跑。

隐藏目录里的工具配置（`.github/`、`.codebuddy/`、`.specify/` 这类）不算项目文档，不进盘点表。

对每份文档记 6 格（表在对话里给，不落盘）：

`路径 | 现在实际回答什么 | 谁在读（地图 / 被引用 / 没人） | 最后改动 | 与代码是否一致 | 观察到的现象`

一致性只抽查能验的：文档里写的命令能不能跑、路径是否存在、模块表里的目录是否存在、STATUS 声称完成的批次有没有对应代码或测试。**不能验的项写「未验证」，不要凭印象判一致。**

### 2. 判病象（7 类）并定范围

| # | 病象 | 判定 | 处置方向 |
| --- | --- | --- | --- |
| 1 | 入口缺失 | 无 `AGENTS.md`，或 L0 不指向任何 L1 | 新建入口；文档超出进门三件时建地图 |
| 2 | 多副本 | 同一事实（版本号、端口、批次名、命令）在 ≥2 处都能改；`AGENTS.md`、`README.md` 里的手写文档清单也算 | 定一个家，其余改指针 |
| 3 | 死文档 | 与代码不符，且除文档清单（地图或待迁走的手写清单）外没有任何引用；惯例文件和生成物按第 4b 步处理，不在此列 | 归档或删除（删除先确认） |
| 4 | 过肥 | `AGENTS.md` > 120 行，或 L1 > 200 行（`README.md` 不按行数判，查它是否复制了结构或接口内容） | 下沉到 L2 或删 |
| 5 | 层次错位 | L0 里写实现细节；L3 的历史被当现状读 | 搬家 |
| 6 | 假进度 | 任何文档说完成或进行中，但无证据或与代码矛盾 | 回填证据或降级状态 |
| 7 | 无归属 | 全文没写「我负责回答什么」，也没有「何时改」 | 补元信息或并掉 |

**一条病象都判不出来 → 不要重构。** 按体检模式出报告，然后停。

**确认点一：不阻塞。** 一行交代后继续做，用户回「停」或改范围再调；不必等回复。确认点二（结构清单）是阻塞的，见第 4 步。

> 这次治 2、6、7 三条；3 号那批历史文档我不动，只在地图上标为 L3。

### 3. 定档与文档集

| 档 | 适用 | 文档集 | 升档触发 |
| --- | --- | --- | --- |
| 最小 | 单人、小工具、几周收尾 | `AGENTS.md` + `STATUS.md`（已有 `README.md` 就保留） | 出现第二个模块 |
| 标准 | 持续迭代、有模块划分 | 最小 + `README.md`；`docs/ARCHITECTURE.md` `docs/CONVENTIONS.md` | 出现「当初为什么否掉 A 方案」的追问 |
| 长期 | 多批次、多 agent、要追溯 | 标准 + `docs/adr/` `docs/plans/` `docs/evidence/` `docs/archive/` | — |

既有项目按“已有文档装得下的最低一档”定档，不按「适用」列硬套。

**文档集是上限，不是清单**：填不出内容的不建，比如没有成文约定就不建 `docs/CONVENTIONS.md`，模板里指向它的句子也一起删。

**地图不看档位，只看文档**：文档超出进门三件（`AGENTS.md` `STATUS.md` `README.md`）就建 `DOC_MAP.md`；没超出就不建，这三个文件名已经说清了各自的用途。多出的 `.md` 会让 `doc-check.sh` 报 FAIL，升档不靠记忆。

**落盘位置固定**：`AGENTS.md` `DOC_MAP.md` `STATUS.md` `README.md` 在根，其余进 `docs/`。理由：根目录每多一份，第一眼要扫的清单就长一分，所以只留进门就要用的文件；`docs/` 不是每个项目都有，有的还是网站目录，地图放根才能让脚本写死路径；`README.md` 必须在根，它是仓库名片。表里的路径是新建时的默认位置：既有项目已有自己的布局时**沿用既有布局**，只改地图，不搬文件；只有治病象才移动文件，并写进迁移映射表。

**层数由判据算，不由档位抄**：每份文档都要被地图或上一层指到，指不到的那层不要建。一份文档只属于一层。

| 层 | 回答什么 | 预算 | 谁读、怎么读 |
| --- | --- | --- | --- |
| L0 入口 | 文档怎么改？去哪查？ | `AGENTS.md` ≤120 行 | agent 每次会话全读 |
| L0 地图 | 我该看哪份？ | `DOC_MAP.md` 词表 ≤50 行，每份文档一行 | agent 按需查询，不自动加载 |
| L1 | 项目是什么、现在到哪、结构如何、什么规矩 | 每份 ≤200 行（`README.md` 除外） | 接手任务的人与 agent |
| L2 | 这个模块/机制为什么这样、怎么用、怎么改 | 无硬限，须被地图指到 | 要用或要动该模块的人 |
| L3 | 当时怎么想、试过什么、证据在哪 | 不限，append-only | 追溯者与复核者 |

L0 按职责定义：两份文件都只做路由，不讲项目知识。入口按读者分：`AGENTS.md` 是 agent 的入口，`README.md` 是人的入口。

### 4. 落 L0：`AGENTS.md` 与 `DOC_MAP.md`

**确认点二：阻塞。** 写盘前一次给出结构清单，等确认再写：要建哪些文件（含完整路径）、每份回答什么问题、哪些旧文档要移动或删除、要改哪些既有正文、`AGENTS.md` 是否要改地图指针以外的段落、`DOC_MAP.md` 的初版词表。清单未获确认不得写盘——此时改动成本接近零，写下去之后每一步都要用户回头核对。

#### 4a. `AGENTS.md`

拷贝 `assets/agents-template.md`，五块顺序固定：

1. 定位（一句话，与 `README.md` 的定位句保持一致。这是唯一允许的重复：agent 每次会话都要先知道自己在哪个项目里，改定位时两处一起改）
2. 当前状态指针（一行：去看 `STATUS.md` 的哪一节；**不在这里复制进度**）
3. 地图指针（地图在哪、怎么查；没有 `DOC_MAP.md` 就删掉这一块）
4. 元规则（≤5 条，只准两类：路由规则、文档维护规则）
5. 改动协议（怎么查该改哪份 + 结构变化先改地图 + 验收命令）

四条硬约束：

- **不复制“哪个事件改哪份文档”。** 这件事只写在 `DOC_MAP.md` 的“时改”段，改动协议只教怎么查；两处都写就是第二个可写副本。
- **不用 `@DOC_MAP.md` 导入地图。** 导入会让地图每次会话都加载，拆分就白做了；用普通路径指过去。
- **产品与技术规范一律下沉。** `AGENTS.md` 里出现接口定义、表结构、命名条款，说明元规则被撑破：搬到 `docs/CONVENTIONS.md`，这里只留一行指针。
- **L0 超预算就下沉，不许缩句糊过去。** 缩句只是把同样的上下文换个说法继续占坑。

#### 4b. `DOC_MAP.md`

文档超出进门三件才做这一节。拷贝 `assets/doc-map-template.md`，按顺序做四件事。

**一、定收录范围。**

| 类别 | 处理 |
| --- | --- |
| 记录项目信息的 `.md`：L0–L2、ADR、plans | 逐份收录 |
| `archive/`、`evidence/`、有人要读的生成文档 | 目录行，一行代表整个目录 |
| `CHANGELOG.md`、`CONTRIBUTING.md` 这类惯例文件 | 原地保留，按实际用途收录；记录历史的算 L3 |
| `Makefile`、`schema/*.yml`、配置代码这类非 `.md` 的权威文件 | 可选收录，`doc-check.sh` 只查路径存在 |
| 模板、第三方文档、没人读的生成物 | 写进豁免块 |
| 隐藏目录里的工具配置 | 不用管，`doc-check.sh` 不扫描 |

ADR 值得逐份收录：它只追加，标签几乎不用维护，又能回答“改这个功能之前有哪些决策约束我”。

**二、定词表。** 三类都写在 `doctags` 块里，标签内容按项目适配。

| 词表 | 来源 | 规模 | 频率规则 |
| --- | --- | --- | --- |
| 主题标签（关于） | 父级先取 `ARCHITECTURE.md` 模块表，再补横切主题 | 父级 3–10 个，文档少就取少，最多两级 | 只算父级：至少覆盖 3 份；最多 40%，文档不超过 20 份时不查上限；子级可以落单；文档少于 10 份都不查 |
| 时机标签（何时读） | 模板起步集，删掉用不到的 | ≤12 个 | 不设，低频的常常是最准的路由 |
| 修改事件（何时改） | 第 7 步的写入时机表，项目可加 | 不限 | 不设，一个事件落到的文档越少越好 |

这里的“文档数”按地图行数算，含 `AGENTS.md`、`DOC_MAP.md`，目录行算一份。这些数字是初值，要调就改 `doc-check.sh` 开头的常量。

**三、写文档行。** 每份文档一行，按目录分组：

```markdown
- `docs/data-domain.md` L2 — 关于【数据-适配层】和【数据-所有权】；在【加功能】和【跨模块改动】时读；在【增删模块】时改
```

- **行内写完整路径。** grep 的结果要能单独看懂。
- **标签一律用 `【】`，词表里也一样，子级写全称。** 没有标识时，搜“设计”会命中所有【推翻设计】。
- **主题标签可以和路径重合。** 它是检索键，不是补充信息，缺了就查不到这份文档。
- **不要为了消 WARN 少打标签。** 第 9 项只是 WARN，标签缺了才会真的漏文档。
- **综述文档按小节打标签。** `README.md` 这类文档跨主题多，只打一两个会漏检。这条来自一次试点，未验证。
- **地图是完整清单。** `AGENTS.md` 和 `DOC_MAP.md` 自己也要有一行。路径必须真实存在，拷模板后先删掉本项目不建的行；不许为了占位建空文档（空文档会被下一次会话当权威读）。
- **地图写路由标签，文档头写边界。** 两处都写整句范围，必有一份先腐坏。判据：地图行里只有标签，文档头写成句子。

**四、校词表。** 这时脚本还没拷进项目，用 `bash <技能>/scripts/doc-check.sh --root <root>`，只看第 7–9 项。地图先行，第 2 项因为文件还没建而报 FAIL 是正常的，收工时必须清零。按第 9 项的 WARN 调整：前缀碰撞就改名，父级覆盖太少就并入别的父级，太多就拆开。

词表权限：初版进确认点二；校词表时的改名和并拆父级不必再确认，收工时一并告诉用户；之后 agent 可以自行加子标签，新增父级或时机标签要用户确认。

**标签和全文搜索都要做。** 标签能找到还没写到某个词的文档，全文搜索能找到标签没覆盖的文档，两者不能互相代替。

### 5. 落 L1 / L2 / L3

每份被地图指向的 `.md`（`AGENTS.md` 除外），首部（H1 之后空一行）必须有：

```markdown
> L1 | 权威：项目现状、批次进度、已知未完成 | 不权威：结构、约定、决策理由
```

- `权威` 写它**负责**回答什么；`不权威` 写**最容易被人误用到这里**的那类事实。第二句比第一句有用——它直接掐死「顺手把别处内容也写进来」。
- 读写时机只在地图，不重复写在这里（两处都写就是第二个可写副本）。
- 层同时写在地图行和这里，`doc-check.sh` 第 4 项核对两处是否一致。
- 头信息写的是文档的职责，不代表内容已核实。已知不实的内容记进 `STATUS.md` 的「已知风险」。

`STATUS.md` 另有规格，它是 agent 判断「下一步做什么」的唯一依据：

```markdown
# 状态

> L1 | 权威：项目现状、批次进度、已知未完成 | 不权威：结构、约定、决策理由

当前焦点：<一句话，指到具体批次或问题>

| 批次 | 目标 | 状态 | 证据 | 更新日期 |
| --- | --- | --- | --- | --- |
| F1 | 建数据层 | 已完成 | `tests/test_store.py` 12 passed；commit a1b2c3d | 2026-10-20 |
| F2 | 接口层 | 进行中 | `docs/plans/F2.md` | 2026-10-26 |
```

- 状态只允许五个值：`未开始` / `进行中` / `已完成` / `受阻` / `已取消`，另加一个过渡值 `进行中（待验证）`。不许再加括号说明。
- **`已完成` 必须填证据**：路径、可复跑命令、commit/PR 三者之一。填不出 → 只能写 `进行中（待验证）`。声称进行中却找不到痕迹，也写这个值。
- 过程叙述进 `plans/`，不进这张表。表只记结果与证据。
- 取消的批次保留行，状态改 `已取消` 并写原因；删行等于抹掉历史。

`README.md` 是人的入口，读者和 `AGENTS.md` 不同，规则也不同：

| 内容 | 归属 |
| --- | --- |
| 定位、能力边界、快速开始、对外限制 | `README.md` 权威 |
| 文档入口 | 只放按读者问题分的几行入口，其中一行指向 `DOC_MAP.md`；不放文档清单 |
| 批次进度、待办 | `STATUS.md`，README 最多留一行指针 |
| 结构、接口细节、完整命令参考 | L1、L2 文档，README 不复制；快速开始只放最短路径 |

- 头信息放在一句话定位之后，不要把定位挤下去；`doc-check.sh` 查前 15 行。
- 不按 200 行判过肥。README 不会每次加载，长度由内容决定；超长时先查是否复制了结构或接口内容。
- 子目录里的 `README.md` 只是普通文档，按它实际回答的问题定层。
- 本技能只定边界。README 正文的写作和评审，有 `readme-guidelines` 技能就转给它，没有也不影响本流程。

README、L2 与 L3 的骨架见 `assets/doc-templates.md`。填不出内容的文档**不要建**——空文档会被下一次会话当权威读。

### 6. 对账与挂门禁

```bash
mkdir -p <root>/scripts
cp <技能>/scripts/doc-check.sh <root>/scripts/doc-check.sh
bash <root>/scripts/doc-check.sh --root <root>
```

| 退出码 | 含义 | 处置 |
| --- | --- | --- |
| 0 | 通过（可能有 WARN） | 收工；WARN 逐条记下理由 |
| 1 | 有 FAIL | 按输出逐条修，改完重跑；不许跳过 |
| 64 | 找不到 `AGENTS.md`，或参数错 | 回第 4 步 |

九项检查：

| # | 检查 | 不通过 |
| --- | --- | --- |
| 1 | 有 `DOC_MAP.md` 时地图可解析；没有时按最小档处理 | FAIL |
| 2 | 地图路径存在，可含非 `.md` | FAIL |
| 3 | `.md` 都被覆盖或写在豁免块里；隐藏目录不扫；无地图时只允许进门三件 | FAIL |
| 4 | 被索引文档前 15 行有 `> Lx \| 权威：… \| 不权威：…`，且层与地图行一致 | WARN |
| 5 | `STATUS` 状态值合法；`已完成` 行证据非空 | FAIL |
| 6 | 文档内相对链接目标存在 | WARN |
| 7 | 地图行三段齐全，标签都在对应词表内 | FAIL |
| 8 | 标签跨类同名 | FAIL |
| 9 | 主题父级频率、未使用的主题标签、前缀碰撞、预算超线 | WARN |

失败路径：

- 第 1 项报没有可解析的地图行 → `docmap` 标记拼错，或行首不是反引号路径；按 `assets/doc-map-template.md` 对齐。
- 第 3 项报超出进门三件 → 这是升档信号，按第 4b 步建 `DOC_MAP.md`，不要靠删文档绕过。
- 第 3 项一片红 → 先加豁免（生成物、临时报告），再逐份归位；**不要为了过检把文件全堆进地图**。
- 第 5 项报状态值非法 → 有人写了「基本完成」这类词；改成五个枚举值之一，过程写进 `plans/`。
- 第 7 项报词表外标签 → 先判断是拼错还是新概念。拼错就改；新概念按词表权限处理，不要为了过检把词塞进词表。
- 第 9 项报频率或碰撞 → 按第 4b 步第四件事调整；确有理由保留就记下理由，它只是 WARN。
- 脚本报 `syntax error` → 项目里的副本被改坏了；重新拷贝，改动提回本技能。

**挂门禁**：片段见 `assets/gate-config.md`。只打印、不代写——改 `.git/hooks` 会影响同仓库所有人，CI 文件要提交，属于用户的仓库决策。

### 7. 维护：写入时机表

维护不是「记得更新文档」，是每类改动都有指定动作。下表是修改事件词表的来源，**不拷进项目**：项目里“哪个事件改哪份文档”只写在 `DOC_MAP.md` 的“时改”段。

| 事件 | 必改（按顺序） | 不用改 |
| --- | --- | --- |
| 【批次收尾】 | `STATUS` 该行状态 + 证据 + 日期 | `ARCHITECTURE`（结构没变时） |
| 【增删模块】，或依赖方向变 | `ARCHITECTURE` 模块表 → 地图 → 新 L2 | `README`（启动方式没变时） |
| 【做取舍】，或否掉了方案 | 新 ADR → `ARCHITECTURE` 对应行加指针 | `STATUS` 只记结果 |
| 【用法变化】 | `README` 用法段 | `CONVENTIONS` |
| 【约定变化】 | `CONVENTIONS` → 若约束 agent 行为，加进 `AGENTS.md` 元规则 | L2 细节 |
| 【结构变化】 | **先**地图 → 再动文件 → 跑 `doc-check.sh` | 其余 |
| 文档与代码冲突 | 描述性文档：改文档；规范性文档：改代码或记例外 | 不许两边各改一半 |
| 【文档被取代】 | 首部加 `已被 <新文档> 取代`，或移 `archive/` | 不许静默删除 |

**算做完的标志是 `doc-check.sh` 退出码 0**，不是「我改完了」。

**定期体检**（每月，或每 20 次提交）：对地图里每份文档跑 `git log -1 --format=%cs -- <路径>`；超过 180 天未改、且 `grep -rl --exclude=DOC_MAP.md <文件名> .` 找不到任何引用 → 列进候选归档，交用户确认后移 `archive/`。再从上次体检后改过的文档里抽 5 份，核对地图行的标签还对不对；发现文档改了、标签没改，记一条使用事件（见 `references/SOURCES.md`）。

## 注意事项

### 冲突裁决：先分描述性还是规范性

文档与代码不一致时，先分类再决定改哪边。判错方向会把正确的代码改成错的。

| 类型 | 例子 | 冲突时 | 依据 |
| --- | --- | --- | --- |
| 描述性 | 现状、结构、进度、模块清单 | 文档错，改文档 | 代码是事实 |
| 规范性 | 约定、契约、需求、安全要求 | 代码错，改代码；做不到就记例外 | 文档是承诺 |
| 分不清 | 一处写「应该」、一处写「实际」；README 的用法、命令参考写的是承诺还是现状 | 进冲突清单，交用户裁决 | 不要自己选一边 |

表里的“改文档”“改代码”是裁决方向，不是本次动作。结构重构期间只记录，内容修订另做一次（见下表「用户要求顺手把内容也改好」）。

### 异常与边界

| 场景 | 处理 |
| --- | --- |
| 项目不是 git 仓库 | 仍可建；「最后改动」改看文件 mtime；`doc-check.sh` 不依赖 git，照跑 |
| 已有 `AGENTS.md` 但无地图，文档超出进门三件 | 按重构：先建 `DOC_MAP.md`，再把既有段落归位；**不整篇重写**，要删的段落列清单确认 |
| `AGENTS.md`、`README.md` 或其他文档里已有手写文档清单 | 按病象 2：清单迁进 `DOC_MAP.md`，原处改成指针；`README.md` 保留按读者问题分的入口 |
| 项目已用 L0–L3 表示别的意思 | 在地图开头声明这里的层指文档层级，不改项目原有说法 |
| `CLAUDE.md` / `.cursorrules` 已存在 | `AGENTS.md` 为唯一权威，其余做软链 `ln -s AGENTS.md CLAUDE.md`。两个真文件即第二个可写副本 |
| 200 份以上 `.md`、monorepo | 只覆盖用户圈定范围；地图按目录分节，未覆盖的目录写进豁免块 |
| 文档全是 API 参考 | 不迁进 L2；生成式文档交给生成工具，地图只留一个指针 |
| 用户要求「顺手把内容也改好」 | 结构重构与内容修订分两次做、各自验收；混在一次里，失败时分不清哪一步错 |
| 旧文档几千行历史 | 不搬正文；路径进地图（L3），文件移 `archive/`，git 历史保留 |
| 两份文档都像权威且互相矛盾 | 进冲突清单；先按「代码/可运行证据优先」给建议，由用户定 |
| 地图某行指向目录 | 允许（`archive/` 一行代表整目录）；目录内新增文件不再逐一登记 |
| 用户中途离场 | 停在已确认范围，不自行扩大；已落盘部分跑一次 `doc-check.sh` 留下状态 |

### 铁律

- **地图先行**：改结构先改地图，再动文件，最后对账。顺序反了，所有读地图的 agent 都读到假图。
- **不静默删除**。删任何文档前列清单、给替代归属、等确认。归档优先于删除。
- **不代写正文**。骨架与头信息是产物；正文属于项目，代写的正文必然与代码脱钩。
- **L0 超预算就下沉**，不许缩句、不许换个说法继续占坑。
- **不许写 `基本完成` `大概做完`**。状态只有五个枚举值；写不准就写进 `plans/`。
- **标签不代替全文搜索。** 标签过期后 agent 会漏文档，还以为没有相关文档，所以两者都做。
- **`doc-check.sh` 只查能对账的部分**。它不评价「写得好不好」——那会退化成打分器，还会让人以为漂移已被自动治理。

### 反模式

| 错法 | 为什么错 / 替代 |
| --- | --- |
| 复制一份 README 当 STATUS | 第二个可写副本，必然分叉。进度只在一个地方写 |
| 把文档清单写回 `AGENTS.md` 或 `README.md` | 第二张地图，必然分叉。清单只在 `DOC_MAP.md` |
| 只查标签，不全文搜索 | 两者各能找到对方漏掉的文档 |
| 为一份文档造一个主题父级 | 父级用来归组；单独的主题放到子级 |
| 用目录结构代替地图 | 目录说明不了「何时读、何时改」，agent 仍要逐份打开 |
| 把规范条文抄进 `AGENTS.md` | 每次会话都付这份上下文；改成一行指针 + 锚点 |
| 为凑层数建空文档 | 指不到就不建；空文档会被当权威读 |
| 让脚本判「内容质量」 | 只能对账结构与枚举值；质量判断交给人和复审 |
| 用图片 / mermaid 画结构 | agent 读不了；用表格 + 路径，能 grep |
| 把计划文档当进度看 | L3 是历史，不是现状；现状只在 `STATUS` |
| 一次重构顺手改内容 | 失败时分不清是结构错还是内容错；分两批 |

### 已知限制

- `doc-check.sh` 复制进项目后**不随技能更新**。这是刻意的：hook 与 CI 必须能在没有本技能副本的机器上跑。要同步时人工比对 `diff <技能>/scripts/doc-check.sh scripts/doc-check.sh`。
- 地图覆盖检查跳过隐藏目录，其余按 `.md` 全量比对，对生成物多的仓库会吵。豁免写在 docmap 豁免块内，不要靠临时改脚本绕过。
- `doc-check.sh` 查不出标签是否说真话。标签过期只能靠全文搜索和定期抽查缓解。
- 标签的检索效果只在一个项目的 12 个 commit 上测过，时机标签的价值尚未验证，数据见 `references/SOURCES.md`。
- 本技能不判断「该不该有这个功能」，也不审文档内容是否正确——那是 `ai-engineering-audit` 与 code review 的范围。
