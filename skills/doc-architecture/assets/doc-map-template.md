# DOC_MAP.md 骨架

> 用法：文档超出进门三件（`AGENTS.md` `STATUS.md` `README.md`）时，只拷 `---` 以下的内容到项目根，`<...>` 全部替换或删掉。
> 主题标签按项目写；时机标签和修改事件是起步集，删掉用不到的，再按需补充。
> 三个 HTML 注释标记不要改名：`doc-check.sh` 靠它们定位词表、文档行和豁免块。
> 文档行格式固定：反引号路径 + 层 + `— 关于…；在…时读；在…时改`，分隔符是全角分号。
> 每个 `【】` 都算标签，词表的定义文字里不要出现 `【】`；子级写全称。

---

# 文档地图

> L0 | 权威：有哪些文档、各讲什么、何时读、何时改 | 不权威：文档内容本身（以各文档和代码为准）

先看词表，再按标签查，查完还要全文搜索。标签能找到还没写到某个词的文档，搜索能找到标签没覆盖的文档：

```bash
grep '【主题' DOC_MAP.md                     # 主题换成词表里的父级
grep '【主题' DOC_MAP.md | grep '【时机】'    # 时机换成词表里的时机标签
```

### 主题标签（关于）

- 【<父级>】<一句定义>：【<父级>-<子级>】【<父级>-<子级>】

### 时机标签（何时读）

- 【上手项目】第一次了解这个仓库
- 【开工】开始一个新开发任务
- 【启动运行】把项目跑起来
- 【加功能】新增或扩展功能
- 【跨模块改动】改动跨层或改变模块边界
- 【推翻设计】想改掉、质疑某项既定设计，或想把它当技术债清理
- 【接手批次】继续一个未完成的计划
- 【排障】排查运行或门禁故障
- 【写测试】新增或修改测试
- 【收工对账】提交前自检
- 【发布上线】发布或部署
- 【查术语】遇到不确定的术语或领域常数

### 修改事件（何时改）

- 【批次收尾】一批任务结束
- 【增删模块】新增、删除模块或依赖方向变化
- 【做取舍】做了取舍或否掉方案
- 【用法变化】对外用法变化
- 【约定变化】约定变化
- 【结构变化】文档结构变化
- 【文档被取代】文档被新文档取代
