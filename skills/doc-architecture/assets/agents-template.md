## 元规则

只放两类：路由（读什么）与文档维护（怎么改）。产品与技术规范去 `docs/CONVENTIONS.md`。

1. 读文档按地图的「何时读」列，一次只读需要的那 1–3 份，不全量读。
2. 同一事实只在一处可写，其余位置只留指针；发现副本就地改成指针。
3. 改文档结构：先改本文件的地图，再动文件，最后跑 `bash scripts/doc-check.sh`。
4. `<项目自己的红线，最多两条；没有就删掉这一条，不要填凑数的话>`

## 改动协议

| 事件 | 必改（按顺序） | 不用改 |
| --- | --- | --- |
| 一批任务收尾 | `STATUS.md` 该行状态 + 证据 + 日期 | 其他 |
| 新增/删除模块 | `docs/ARCHITECTURE.md` 模块表 → 本文件地图 → 新 L2 | `README.md` |
| 做了取舍 | 新 ADR → `docs/ARCHITECTURE.md` 加指针 | `STATUS.md` 只记结果 |
| 文档结构变化 | **先**本文件地图 → 再动文件 → `doc-check.sh` | 其他 |

验收：`bash scripts/doc-check.sh` 退出码 0。
